# [EPIC-04] Фінанси: вартість, прибуток і прогноз

## 1. Загальний опис

Дати адміністратору («діду») те, що його найбільше цікавить: скільки коштує дитина, скільки садок заробляє й витрачає і скільки заробляв би за іншої кількості дітей. Усі суми й ставки беруться з налаштувань, які дід змінює без зміни коду (NFR-06).

Принцип епіку: **гроші рахуються з поточного стану бази.** Звіт і прогноз нічого не зберігають: вони щоразу обчислюються з дітей, груп, працівників і налаштувань. Тому звіт завжди відповідає даним, а зміна ціни одразу видна у звіті.

## 2. Межі епіка (Scope)

### In-Scope

- Фінансові налаштування: ціни, знижки, зарплати, вартість приміщень (FR-010, FR-016).
- План оплати дитини (щомісячно чи за рік) і розрахунок її вартості (FR-012, FR-013).
- Звіт про доходи, витрати й прибуток по групах і по садку за методом нарахування (FR-017).
- Прогноз прибутку для гіпотетичної кількості дітей (розділ 2.1 вимог).
- Покриття тестами: сервіси, HTTP, кожна формула.

### Out-of-Scope

- Рахунки й платежі (FR-014, NFR-11) і звіт за отриманими платежами — TS-04.5, лише якщо залишиться час після розкладу.
- Звіт за конкретний минулий місяць: система не зберігає минулих станів (коли дитина прийшла чи пішла, які були ціни). Звіт показує доходи й витрати за місяць при поточному стані. Справжні періоди з'являться разом із рахунками й платежами, що мають дати (TS-04.5).
- Різна кількість робочих днів у різних місяцях: завжди значення з налаштувань (22, BR-51).
- Податки.

## 3. Декомпозиція задач (Breakdown)

### 🛠 Technical Stories

- [x] **TS-04.1: Фінансові налаштування (FR-010, FR-016, NFR-06)**
    - **Опис:** Окрема колекція з одним записом налаштувань. Якщо запису немає, при старті він створюється зі значеннями з вимог; далі дід змінює будь-яке значення.

    - **Значення за замовчуванням:**

        | Що                                         | Значення                | Звідки                  |
        | ------------------------------------------ | ----------------------- | ----------------------- |
        | Навчання на місяць                         | 15 000                  | BR-20                   |
        | Річна знижка                               | 12%                     | BR-28                   |
        | Робочих днів у місяці                      | 22                      | BR-51                   |
        | Харчування за день, ціна для батьків       | 2 р. — 300 … 5 р. — 600 | BR-22, BR-23            |
        | Харчування за день, собівартість для садка | як ціна                 | BR-33                   |
        | Менеджер                                   | 80 000                  | BR-34                   |
        | Викладач                                   | 40 000                  | BR-35                   |
        | Помічник: база / за дитину понад поріг     | 20 000 / 3 000          | BR-36, BR-39            |
        | Вихователь: за дитину / понад поріг        | 2 000 / 5 000           | BR-37, BR-38            |
        | Поріг дітей у групі для доплат             | 12                      | BR-38, BR-39            |
        | Оренда приміщення на місяць                | 50 000                  | FR-016, рішення команди |

    - **Ендпоінти:** `GET /api/finance/settings` (дід, менеджер), `PATCH /api/finance/settings` (лише дід, BR-24, BR-40).

    - **Acceptance Criteria:**
        - Схема перевіряє лише діапазони: суми й кількості не від'ємні, знижки від 0 до 1. Жодних зашитих значень.
        - Зміна налаштувань потрапляє в історію змін, як будь-яка інша зміна в базі.
        - Нова ціна одразу діє у вартості дитини, звіті й прогнозі.

- [x] **TS-04.2: Вартість для дитини (FR-012, FR-013)**
    - **Опис:** Дитина отримує поле `paymentPlan`: `MONTHLY` (за замовчуванням) або `ANNUAL`. `GET /api/kids/:id/price` повертає розбивку вартості.

    - **Розбивка за місяць:**
        1. базова вартість навчання;
        2. пільга дитини;
        3. навчання після пільги;
        4. річна знижка (лише для `ANNUAL`), від суми після пільги;
        5. харчування: ціна за день для віку дитини × робочі дні;
        6. підсумок за місяць; для `ANNUAL` ще й сума навчання за рік, яку сплачують наперед.

    - **Acceptance Criteria:**
        - Пільга й річна знижка діють лише на навчання (BR-30, BR-31); харчування сплачується щомісяця (BR-32).
        - План оплати, як і пільгу, змінює лише дід.
        - Батьки бачать вартість лише своїх дітей; дід і менеджер — усіх.

- [x] **TS-04.3: Звіт про прибуток (FR-017)**
    - **Опис:** `GET /api/finance/report`, лише для діда. Метод обліку — нарахування: що садок заробляє й витрачає за місяць при поточному складі й поточних цінах.

    - **Структура:**
        - **Групи:** для кожної — дохід від навчання, дохід від харчування, витрати на харчування, зарплата вихователя, зарплата помічника, приміщення, прибуток.
        - **Спільні витрати:** менеджери (за кількістю акаунтів `MANAGER`), викладачі, приміщення без групи (для занять чи вільні), базова зарплата помічників без групи. Вихователь без групи отримує 0: його зарплата залежить лише від дітей (BR-37).
        - **Підсумок:** загальні дохід, витрати й прибуток.

    - **Acceptance Criteria:**
        - Звіт явно вказує метод обліку (`ACCRUAL`), що суми місячні (`amountsPer: MONTH`), і момент розрахунку (`asOf`).
        - Дохід від харчування й витрати на харчування — окремі рядки, навіть якщо рівні (BR-33).
        - Річна оплата враховується як 1/12 за кожен місяць, тож передоплата не збільшує прибуток одного місяця (FR-017).
        - Дитина без групи не ходить у садок і до звіту не входить.
        - Сума прибутків груп мінус спільні витрати дорівнює загальному прибутку.

- [x] **TS-04.4: Прогноз прибутку (розділ 2.1)**
    - **Опис:** `POST /api/finance/forecast`, лише для діда. Відповідає на питання «скільки садок заробляв би з такою кількістю дітей».

    - **Вхід:** кількість дітей кожного віку, наприклад `{ "kids": { "2": 35, "3": 40, "4": 20, "5": 18 } }`; необов'язково — середня пільга й частка дітей на річній оплаті.

    - **Acceptance Criteria:**
        - Прогноз сам шукає найприбутковіший розподіл: для кожного віку перебирає кількість груп від найменшої (групи по 20, BR-02, BR-03) до однієї групи на дитину, у межах 15 груп загалом (BR-19), діти розподіляються між групами порівну. Повні групи не завжди найвигідніші: за налаштуваннями за замовчуванням група з 12–13 дітей дає більше, бо дитина понад поріг коштує додаткових доплат.
        - Для порівняння відповідь містить і варіант з найменшою можливою кількістю груп, де діти розподілені порівну (`fewestGroups`).
        - Понад 15 груп (BR-19) дає `422` з тим, скільки груп потрібно.
        - Ціни й зарплати — з налаштувань; спільні витрати (менеджери, викладачі, приміщення для занять) — як зараз.
        - Відповідь має ту саму структуру, що й звіт, тож прогноз і поточний стан легко порівняти.
        - Прогноз нічого не змінює в базі.
        - Відповідь містить і поточний підсумок (`now`), тож видно, на скільки зміниться прибуток.
        - Частка річної оплати округлюється до цілих дітей у кожній групі.

- [ ] **TS-04.5: Рахунки й платежі (FR-014, NFR-11) — якщо залишиться час**
    - **Опис:** Рахунок за місяць для дитини з рядками, зафіксованими в момент створення; платіж, прив'язаний до рахунку; звіт за отриманими платежами (`?basis=cash`).
    - **Acceptance Criteria:**
        - Повторний платіж з тим самим заголовком `Idempotency-Key` повертає вже створений платіж, а не створює другий.
        - Зміна цін не змінює вже виставлені рахунки.
        - Батьки бачать і оплачують лише рахунки своїх дітей.

## 4. Перелік User Stories / Задач

- [x] **US-04.1: Керування фінансовими значеннями**
    - **Як** дід, **я хочу** змінювати ціни, знижки й зарплати, **щоб** не просити програміста про кожну зміну.
- [x] **US-04.2: Вартість для батьків**
    - **Як** батьки, **я хочу** бачити, скільки коштує навчання й харчування моєї дитини і скільки я заощаджу на річній оплаті, **щоб** вибрати план оплати.
- [x] **US-04.3: Прибуток садка**
    - **Як** дід, **я хочу** бачити доходи, витрати й прибуток кожної групи й садка загалом, **щоб** знати, що приносить гроші.
- [x] **US-04.4: Прогноз**
    - **Як** дід, **я хочу** порахувати прибуток для гіпотетичної кількості дітей, **щоб** вирішити, чи варто набирати більше.

## 5. Критерії готовності (Definition of Done)

- [x] Кожне фінансове значення з вимог змінюється через `PATCH /api/finance/settings` і впливає на розрахунки без зміни коду.
- [x] Звіт і прогноз доступні лише діду; вартість дитини — діду, менеджеру й батькам цієї дитини.
- [x] Кожна формула покрита тестом з розрахунком «на папері» в назві або коментарі.
- [x] Postman-колекція містить запити налаштувань, вартості, звіту й прогнозу.
- [x] `npm test` і `npm run lint` проходять.
