# [EPIC-01] Створення базових CRUD-операцій

## 1. Загальний опис
Забезпечити базовий програмний інтерфейс (API) та persistence-шар для управління основними сутностями системи (Create, Read, Update, Delete). Це створить фундамент для бізнес-логіки наступних епіків.

## 2. Межі епіка (Scope)
### In-Scope
- Реаліазція файлового persistance-шару, що функціонуватиме на `JSON`-файлах.
- REST API ендпоінти для сутностей: `Kid`, `Group`, `Teacher` тощо.
- Валідація вхідних даних (DTO).
- Базова обробка помилок (`400`, `404`, `500`, `200`, `201`).
- Покриття юніт- та інтеграційними тестами.

### Out-of-Scope
- Автентифікація та авторизація - буде в EPIC-03.
- Складна бізнес-логіка - буде в EPIC-02
- Реалізація розкладу
- Реалізація підтримки фінансових операцій
- Реалізація оптимізаційної частини системи

## 3. Декомпозиція задач (Breakdown)

### 🛠 Technical Stories (Інфраструктура & Engine)
- [ ] **TS-01.1: Розробка File Storage Engine Core**
  - **Опис:** Створити базовий клас/модуль для читання та запису структурованих даних у файли.

  - **Acceptance Criteria:**
    - Розроблена система дає змогу декларативно виконувати запити SELECT
    - Розроблена система надає інтерфейс для створення, видалення та оновлення сутностей
    - Розроблена система генерує UUIDv7 первинні ключі для сутностей
    

- [ ] **TS-01.2: Реалізація логіки індексації**
  - **Опис:** Забезпечити швидкий пошук за атрибутами, що часто використовуються в запитах пошуку (SELECT-ах). Це досягаєтсья шляхом збереєенян кеш-словників в оперативній пам'яті системи

  - **Acceptance Criteria:**
    - Розроблена система не вимагає у розробника, що пише запит, напряму модифікувати та синхронізувати індекс-словники.
    - Розроблена система запобігає FULL TABLE SCAN при пошуку за полями, що часто використовуються
    - Розроблена система самостійно заповнює індекс-словники при ініціалізації


- [ ] **TS-01.3: Реалізація ACID**
  - **Опис:** Забезпечити надійність persistance-шару шляхом атомарних записів, уникнення аномалій читання, запису, уникнення Race conditions тощо.

  - **Acceptance Criteria:**
    - Розроблена система гарантує атомарний запис за допомогою створення тимчасових файлів та атомарного перейменування файлу-копії в оригінал
    - Розроблена система гарантує уникнення Race Condition при подійному паралельному записі за допомогою черг на primary key.
    - Розроблена система надає змогу писати імперативні транзакції, що гарантують атомарність на рівні декількох файлів.

- [ ] **TS-01.4: Реалізація CRUD-операцій**
  - **Опис:** Створити ендпойнти для CRUD операцій

  - **Acceptance Criteria:**
    - Розроблена шарована архітектура (рутери, контролери, сервіси, репозиторії).
    - Розроблено дизайн документ для REST API.
    - Розроблено та реалізовано схему бази даних.
    - Система дає змогу створювати керувати сутностями через спеціальні відведені ендпойнти.

## 4. Перелік User Stories / Задач
- [ ] **US-01.1: Створення базових сутностей (`Kid`, `Group`, `Teacher`)**
  - **Як** адміністратор, **я хочу** створювати нові записи сутностей, **щоб** заповнювати первинну базу даних системи.
- [ ] **US-01.2: Отримання деталей та списків**
  - **Як** адміністратор, **я хочу** отримувати деталі сутності за `ID` та списки з базовою фільтрацією, **щою** отримувати актуальний стан системи.
- [ ] **US-01.3: Оновлення даних**
  - **Як** адміністратор, **я хочу** оновлювати поля сутностей за їх `ID` з валідацією нових даних, **щоб** змінювати більше неакутальні дані.
- [ ] **US-01.4: Видалення сутностей**
  - **Як** адміністратор, **я хочу** видаляти записи з системи, **щоб** видаляти більше неактуальні дані.

## 5. Критерії готовності (Definition of Done)
- Реалізований надійний та зручний Persistance шар системи.
- Реалізовані всі шари для кожної головної сутності (рутер, контролер, сервіс, репозиторій)
- Користувач може керувати сутностями за допомогою спеціальних ендпойнтів.
