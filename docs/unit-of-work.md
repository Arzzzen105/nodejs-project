# Unit of Work: транзакції в репозиторіях і сервісах

`UnitOfWork` ([src/repositories/unit-of-work.js](../src/repositories/unit-of-work.js)) дає змогу виконувати кілька операцій з базою в одній транзакції, не передаючи транзакцію з методу в метод. Сервіси й репозиторії не знають, хто відкрив транзакцію: вони просто загортають свою роботу в `uow.run(...)`.

## Два методи

```js
const uow = new UnitOfWork(db); // один на застосунок

uow.run(async () => { ... }, options); // виконати в транзакції
uow.executor(); // на чому викликати get/list/create/update/delete
```

- **`run(body, options)`** відкриває транзакцію, а якщо `run` уже виконується вище за стеком викликів, **приєднується** до неї. Комміт відбувається, коли завершується той `run`, що відкрив транзакцію. `options` (`timeout`) діють лише для нової транзакції.
- **`executor()`** повертає поточну транзакцію всередині `run` і базу поза ним. Репозиторій завжди звертається до бази через нього.

## Репозиторій

```js
export class ParentRepository {
    #uow;

    constructor(uow) {
        this.#uow = uow;
    }

    #db() {
        return this.#uow.executor();
    }

    // одна операція: run не потрібен, вона й так атомарна
    async findById(id) {
        return this.#db().get('parents', id);
    }

    // кілька читань, які мають бачити один стан бази, тому run
    async findWithKids(id) {
        return this.#uow.run(async () => {
            const parent = await this.#db().get('parents', id);
            const { items: kids } = await this.#db().list('kids', {
                predicate: inList('id', parent.childIds),
            });
            return { ...parent, kids };
        });
    }
}
```

`run` потрібен, щойно метод робить **більше однієї** операції: і для записів (щоб вони відбулися разом або не відбулися взагалі), і для читань (щоб між ними не пройшов чужий комміт).

Методи репозиторіїв завжди `async`, навіть якщо в них один рядок. `executor()` у приреченій транзакції (правило 2) кидає помилку синхронно, і лише `async` перетворює її на відхилений Promise. Без `async` метод кидав би помилку ще до того, як поверне Promise, і `repo.findById(id).catch(...)` чи `Promise.all([...])` її б не побачили.

## Сервіс

```js
async deleteKid(kidId) {
    return this.#uow.run(async () => {        // відкриває транзакцію
        const kid = await this.#kids.findById(kidId);
        const parents = await this.#parents.findByKid(kidId); // приєднується
        await this.#notes.deleteByKid(kidId);                  // приєднується
        await this.#kids.delete(kidId);
        // ... правила FR-018
    });
}
```

Сервіс, що викликає інший сервіс, працює так само: внутрішній `run` приєднується до зовнішнього.

## Правила

1. **Будь-який `throw` у транзакції відкочує її всю, і назовні виходить перша помилка.** Вона доходить до `run`, який відкрив транзакцію, і той кидає її далі як є. Тож `HttpError` із сервісу, наприклад `409 GROUP_IS_FULL` з вкладеного сервісу, дійде до обробника помилок і до клієнта без змін. Вкладених транзакцій немає: є одна бізнес-операція, і виняток скасовує її цілком.
2. **Перехопити помилку вкладеного `run` і продовжити не вийде.** Зміни, які він встиг зробити до помилки, вже в транзакції, тож вона приречена. Після такої помилки будь-яке звернення до бази в цій транзакції (`executor()`, вкладений `run`) одразу кидає ту саму першу помилку, а якщо зовнішній код усе ж завершиться успішно, `run` однаково відкотить транзакцію й кине її. Якщо дальші дії залежать від умови, перевірте її **перед** викликом:

    ```js
    // погано: виняток як розгалуження
    try {
        await groups.deleteIfEmpty(id);
    } catch {
        /* ... */
    }

    // добре
    if (await groups.isEmpty(id)) await groups.delete(id);
    ```

    Окрема операція (`executor().create(...)`) — не `run`, і її помилку перехопити можна: невдала операція нічого не змінює.

3. **Не викликайте `db` напряму.** Якщо всередині `run` звернутися до бази повз `executor()`, рушій відповість `INVALID_TRANSACTION_USE`. Це захист від взаємоблокування, а не помилка UoW.
4. **Транзакція блокує записи інших, поки триває.** Записувач у базі один, тож у `run` не варто робити нічого повільного, наприклад звертатися до зовнішніх сервісів. Читання поза транзакцією не блокуються.
5. **Ліміт `list` — 500 записів.** Для «всіх дітей групи» цього досить. Для вибірок, де записів може бути більше, потрібна пагінація.
