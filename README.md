## 🛠️ Розробка

```bash
npm install
npm run dev    # сервер з автоперезапуском на тимчасовій базі
npm test       # тести
npm start      # сервер на справжній базі database/
npm run db:clear   # очищає справжню базу database/: лишаються тільки config.json
```

`npm run db:clear` видаляє всі записи, історію змін (`.changes/`) і незавершений журнал. Схеми колекцій (`<колекція>/config.json`) лишаються. Перед видаленням команда показує, що саме зникне, і просить ввести `yes`. `-- --dry-run` лише показує, `-- --yes` видаляє без питання. Поки базою користується сервер (`npm start`), команда відмовляє: спершу зупиніть сервер. Тека бази — `DATABASE_DIR`, як у сервера. Для `npm run dev` команда не потрібна: він щоразу стартує з порожньої копії.

`npm run dev` щоразу стартує з **порожньої** бази: схеми колекцій (`database/*/config.json`) копіюються в `.dev-db/`, сервер працює на цій копії, а після зупинки (Ctrl+C) вона видаляється. Справжня `database/` при цьому не змінюється.

- Дані переживають автоперезапуск після збереження файлу, але не перезапуск `npm run dev`.
- Зміни в `database/*/config.json` підхоплюються лише після перезапуску `npm run dev`.
- Якщо сесію вбили жорстко і `.dev-db/` лишилась, наступний `npm run dev` її прибере.
- **Windows:** зупиняйте `npm run dev` лише через Ctrl+C у терміналі. Кнопка «Stop» в IDE на Windows завершує процес примусово: сервер, запущений обгорткою, лишається працювати й тримає порт і базу, тож наступний `npm run dev` відмовиться стартувати. У такому разі завершіть зайві процеси `node.exe` у диспетчері задач.

### Довідник API

Після запуску сервера відкрийте **http://localhost:3000/api/docs**: Swagger UI з усіма ендпоінтами, ролями, параметрами, тілами, відповідями й помилками. Отримайте токен через `POST /api/auth/login` (кнопка «Try it out»), натисніть **Authorize**, вставте токен — і запити можна виконувати просто зі сторінки. Сам документ OpenAPI 3.1 — `/api/openapi.json`: його можна імпортувати в Postman. Як він будується, описано в [controllers.md](docs/architecture/controllers.md#6-довідник-api-nfr-08).

### Вхід

Усі запити до `/api`, крім `POST /api/auth/login`, потребують токена в заголовку `Authorization: Bearer <токен>`. Токен видає вхід:

```bash
curl -X POST localhost:3000/api/auth/login \
    -H 'content-type: application/json' \
    -d '{"username":"admin","password":"admin-password"}'
```

У [Postman-колекції](docs/postman/Kindergarten%20API.postman_collection.json) почніть з `Auth / Login as admin`: токен збережеться в змінну колекції, і решта запитів надсилатиме його сама. Папка `Roles` наприкінці входить від імені менеджера, вихователя й батьків і показує, кого з дітей бачить кожна роль. Папки `Demo: ...` показують фінанси: `Demo: BA example` створює постійні витрати з моделі BA (1 менеджер, 6 викладачів, 5 кімнат для занять) і перевіряє тестами кожну тезу BA, `Demo: group size` — чому групи по 12–13 вигідніші ([аналіз](docs/analysis/group-size-and-profit.md)), `Demo: discounts` — вплив пільг. `Demo: schedule` додає предмети з вимог, викладачів, кімнати й другу групу, генерує розклад, показує вдалий перенос заняття і перенос із конфліктом, публікує розклад і дивиться на нього очима викладача. Запускайте їх на свіжій базі (перезапустіть `npm run dev`): числа в тестах розраховані на порожній садок.

`npm run dev` сам створює діда `admin` з паролем `admin-password` і виводить їх у консоль. Для `npm start` скопіюйте `.env.example` у `.env` і впишіть значення: `npm start` читає `.env` сам. Файл `.env` git ігнорує. Змінні:

| Змінна           | Що задає                                                             | За замовчуванням |
| ---------------- | -------------------------------------------------------------------- | ---------------- |
| `JWT_SECRET`     | ключ підпису токенів; без нього сервер не стартує                    | —                |
| `TOKEN_TTL`      | термін дії токена: `30m`, `8h`, `7d`                                 | `8h`             |
| `ADMIN_USERNAME` | логін першого діда; потрібен, лише поки в базі немає жодного акаунта | —                |
| `ADMIN_PASSWORD` | пароль першого діда                                                  | —                |

### Демо-садок

Щоб помацати систему на повному садку, заповніть порожню базу:

```bash
npm run dev     # перший термінал
npm run seed    # другий термінал
```

Скрипт ([scripts/seed.js](scripts/seed.js)) через API створює 15 груп з вихователями, помічниками й кімнатами, 190 дітей у ~160 сім'ях (частина з двома дітьми), 6 предметів з викладачами, спортзал і кімнати для занять, пільги, річні плани, акаунти всіх ролей, публікує розклад і виставляє рахунки за поточний місяць: приблизно 70% сімей їх оплачують, а сім'я акаунта `parent` лишається з неоплаченими. Він проходить через усі бізнес-правила, тож діагностика після нього порожня. Дані щоразу однакові; база, де вже є групи, не змінюється. Адреса сервера — `SEED_URL` (за замовчуванням `http://localhost:3000`).

Садок можна задати параметрами (`npm run seed -- --help` покаже всі):

```bash
npm run seed -- --groups 8 --kids 120        # 8 груп, 120 дітей
npm run seed -- --kids 60                    # групи по 4 дитини: садок у збитку
npm run seed -- --kids 300                   # майже повний садок
npm run seed -- --annual 1 --paid 1          # усі на річному плані й усі оплатили
npm run seed -- --no-schedule                # розклад генерувати наживо
```

| Параметр        | За замовчуванням | Що задає                                                      |
| --------------- | ---------------- | ------------------------------------------------------------- |
| `--groups`      | 15               | груп, 1–15 (BR-19); вік по колу: 2, 3, 4, 5, 2, …             |
| `--kids`        | 190              | дітей усього, порівну по групах; не більше 20 у групі (BR-03) |
| `--annual`      | 0.25             | частка дітей на річному плані                                 |
| `--discounts`   | 0.2              | частка дітей з пільгою (10%, 20% або 30%)                     |
| `--speech`      | 0.07             | частка дітей, яким потрібен логопед                           |
| `--paid`        | 0.7              | частка сімей, що оплатили рахунки цього місяця                |
| `--random`      | 2026             | зерно випадковості: інше число — інший садок                  |
| `--no-schedule` | —                | не генерувати й не публікувати розклад                        |
| `--no-invoices` | —                | не виставляти рахунки                                         |

Неможливі значення відхиляються ще до запису в базу. Ті самі параметри щоразу дають той самий садок. Прогулянка Postman розрахована на садок за замовчуванням.

Акаунти: `manager`, `educator`, `teacher`, `parent`, пароль кожного — `<логін>-password`. Далі відкрийте [Kindergarten tour](docs/postman/Kindergarten%20tour.postman_collection.json): 180 запитів, що показують увесь API на цьому садку — CRUD кожної сутності, бізнес-правила в дії (ліміти груп і кімнат, вік групи, стать батьків, видалення дитини разом з батьками, історія змін запису), фінанси, рахунки й платежі (батьки оплачують рік і місяць одним платежем, повторний запит з тим самим `Idempotency-Key` не створює другого платежу, звіт за отриманими грошима), розклад від генерації до публікації, діагностику і погляд кожної ролі. Спершу `Start here: log in`, далі папки по черзі або вся колекція через Runner. Колекцію можна запускати скільки завгодно разів: що створює, те й видаляє, що змінює — повертає (лише щоразу публікує новий розклад, а оплачені рахунки й платіж демо-дитини лишаються в історії: платежі не видаляються).

### Знімок бази

У бази немає СУБД з клієнтом, тож її стан показує окрема сторінка:

```bash
npm run dev        # перший термінал (і npm run seed, якщо потрібні дані)
npm run snapshot   # другий термінал → snapshot.html
```

Скрипт ([scripts/snapshot.js](scripts/snapshot.js)) читає все через API від імені діда і пише один HTML-файл без зовнішніх залежностей. Сторінку можна відкрити в браузері або роздрукувати в PDF. На ній:

- огляд з кількістю записів, прибутком і діагностикою;
- групи, діти по групах, батьки, персонал, предмети, кімнати й пільги;
- розклад: тиждень кожної групи. Показується опублікований, а за його відсутності — чорновик;
- гроші: налаштування, прибуток за нарахуваннями й за отриманими платежами;
- рахунки й платежі, облікові записи без паролів, останні 50 змін.

Адреса сервера — `SNAPSHOT_URL`, файл — `SNAPSHOT_FILE`; вхід — через `ADMIN_USERNAME`/`ADMIN_PASSWORD`, як у seed. На сторінці персональні дані, тому `snapshot.html` не потрапляє в Git.

На продакшен-сервері обов'язково задайте `NODE_ENV=production`. Без цього лишиться увімкненим `/api/test`, через який можна обійти бізнес-правила.
