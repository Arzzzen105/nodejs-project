## 🛠️ Розробка

```bash
npm install
npm run dev    # сервер з автоперезапуском на тимчасовій базі
npm test       # тести
npm start      # сервер на справжній базі database/
```

`npm run dev` щоразу стартує з **порожньої** бази: схеми колекцій (`database/*/config.json`) копіюються в `.dev-db/`, сервер працює на цій копії, а після зупинки (Ctrl+C) вона видаляється. Справжня `database/` при цьому не змінюється.

- Дані переживають автоперезапуск після збереження файлу, але не перезапуск `npm run dev`.
- Зміни в `database/*/config.json` підхоплюються лише після перезапуску `npm run dev`.
- Якщо сесію вбили жорстко і `.dev-db/` лишилась, наступний `npm run dev` її прибере.
- **Windows:** зупиняйте `npm run dev` лише через Ctrl+C у терміналі. Кнопка «Stop» в IDE на Windows завершує процес примусово: сервер, запущений обгорткою, лишається працювати й тримає порт і базу, тож наступний `npm run dev` відмовиться стартувати. У такому разі завершіть зайві процеси `node.exe` у диспетчері задач.

### Вхід

Усі запити до `/api`, крім `POST /api/auth/login`, потребують токена в заголовку `Authorization: Bearer <токен>`. Токен видає вхід:

```bash
curl -X POST localhost:3000/api/auth/login \
    -H 'content-type: application/json' \
    -d '{"username":"admin","password":"admin-password"}'
```

У [Postman-колекції](docs/postman/Kindergarten%20API.postman_collection.json) почніть з `Auth / Login as admin`: токен збережеться в змінну колекції, і решта запитів надсилатиме його сама. Папка `Roles` наприкінці входить від імені менеджера, вихователя й батьків і показує, кого з дітей бачить кожна роль. Папки `Demo: ...` показують фінанси: `Demo: BA example` створює постійні витрати з моделі BA (1 менеджер, 6 викладачів, 5 кімнат для занять) і перевіряє тестами кожну тезу BA, `Demo: group size` — чому групи по 12–13 вигідніші ([аналіз](docs/analysis/group-size-and-profit.md)), `Demo: discounts` — вплив пільг. `Demo: schedule` додає предмети з вимог, викладачів, кімнати й другу групу, генерує розклад, показує вдалий перенос заняття і перенос із конфліктом, публікує розклад і дивиться на нього очима викладача. Запускайте їх на свіжій базі (перезапустіть `npm run dev`): числа в тестах розраховані на порожній садок.

`npm run dev` сам створює діда `admin` з паролем `admin-password` і виводить їх у консоль. Для `npm start` скопіюйте `.env.example` у `.env` і впишіть значення: `npm start` читає `.env` сам. Файл `.env` git ігнорує. Змінні:

| Змінна           | Що задає                                                             | За замовчуванням |
| ---------------- | -------------------------------------------------------------------- | ---------------- |
| `JWT_SECRET`     | ключ підпису токенів; без нього сервер не стартує                    | —                |
| `TOKEN_TTL`      | термін дії токена: `30m`, `8h`, `7d`                                 | `8h`             |
| `ADMIN_USERNAME` | логін першого діда; потрібен, лише поки в базі немає жодного акаунта | —                |
| `ADMIN_PASSWORD` | пароль першого діда                                                  | —                |

На продакшен-сервері обов'язково задайте `NODE_ENV=production`. Без цього лишиться увімкненим `/api/test`, через який можна обійти бізнес-правила.
